## 2. Logic Chain

1. **Trigger Recursion Logic**:
   - In SQLite, triggers configured as `AFTER UPDATE ON T FOR EACH ROW WHEN OLD.col IS NEW.col BEGIN UPDATE T SET col = ... WHERE id = NEW.id; END;` evaluate `WHEN` on every update to table `T`.
   - When the trigger executes `UPDATE books SET updated_at = strftime(...)`, inside that recursive update statement `OLD.updated_at` is the timestamp before the trigger ran. If that timestamp was generated in the same UTC second, `strftime('%Y-%m-%dT%H:%M:%SZ', 'now')` produces the exact same string value.
   - Thus, in the recursive invocation: `OLD.updated_at == NEW.updated_at`.
   - The `WHEN` clause evaluates to TRUE again.
   - When `PRAGMA recursive_triggers = ON` (standard in Qt and complex database workflows), the trigger fires again and recurses infinitely until SQLite throws `too many levels of trigger recursion`.
   - Hardening the trigger condition with `AND strftime('%Y-%m-%dT%H:%M:%SZ', 'now') != OLD.updated_at` empirically breaks this loop, allowing rapid updates within the same second without error and advancing the timestamp once a second elapses.

2. **Index Optimization Logic**:
   - Declaring a column `UNIQUE` automatically creates a unique B-Tree index in SQLite. An additional `CREATE INDEX` on the same column creates a duplicate B-Tree. Both B-Trees must be updated on every INSERT, UPDATE, and DELETE, causing write amplification with 0 query benefit.
   - SQLite `LIKE` operator is case-insensitive for ASCII characters. A standard `INDEX ON books(title)` creates a `BINARY` sorted index, which cannot be used for `LIKE 'prefix%'`. Defining the index as `CREATE INDEX idx_books_title ON books(title COLLATE NOCASE)` allows the query planner to transform prefix `LIKE` into a bounded range scan `(title > ? AND title < ?)`.

## 3. Caveats

- **SQLite Default `recursive_triggers` Setting**: In raw SQLite C API, `recursive_triggers` defaults to `OFF` unless explicitly toggled or triggered by nested cascades. However, enterprise desktop applications using Qt (`QSqlDatabase`) or multi-threaded background workers often enable `PRAGMA recursive_triggers = ON;`, making this defect critical for real-world deployments.
- **Substring Searches**: No B-tree index can accelerate substring searches of the form `LIKE '%substring%'`; full-text search (SQLite FTS5) would be required for mid-word searches. However, prefix search (`LIKE 'query%'`) is immediately accelerated by `COLLATE NOCASE`.
- **Existing Positive Behaviors**: The schema's foreign key cascades, data types, and check constraints for progress percent and color palette are robust and verified.

## 4. Conclusion

**Verdict: `REQUEST_CHANGES`**

The schema deliverable `replica/schema.sql` cannot be approved in its current state due to the critical trigger recursion defect and indexing deficiencies. The changes required are straightforward, scoped, and empirically validated.

### Required Actions for `worker_m3`:
1. **Harden all 4 `updated_at` triggers** (`trg_books_updated_at`, `trg_reading_progress_updated_at`, `trg_annotations_updated_at`, `trg_app_settings_updated_at`) by updating their `WHEN` clause:
   ```sql
   WHEN OLD.updated_at IS NEW.updated_at AND strftime('%Y-%m-%dT%H:%M:%SZ', 'now') != OLD.updated_at
   ```
2. **Remove redundant index**: Delete `CREATE INDEX IF NOT EXISTS idx_books_file_hash ON books(file_hash);` (already covered by `books.file_hash UNIQUE`).
3. **Optimize title search index**: Change `idx_books_title` to:
   ```sql
   CREATE INDEX IF NOT EXISTS idx_books_title ON books(title COLLATE NOCASE);
   ```
4. **Add missing author lookup index**:
   ```sql
   CREATE INDEX IF NOT EXISTS idx_books_author ON books(author);
   ```
5. **Add defensive check constraints**:
   - `books.file_size INTEGER NOT NULL CHECK(file_size >= 0)`
   - `folders.parent_id INTEGER REFERENCES folders(id) ON DELETE SET NULL CHECK(parent_id != id)`
